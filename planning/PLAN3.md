# PLAN3 — 이탈 의사결정 지표 확장

작성일: 2026-08-30
선행: PLAN2 (Priority 1~3 완료), PR #13 (대시보드 개편)

---

## 배경

대시보드가 "이 고객은 위험합니다"까지는 답하지만, 운영진의 다음 질문
**"그래서 누구에게, 언제, 얼마를 쓸까요"** 에는 답하지 못했다.
이 문서는 그 간극을 메우는 지표를 우선순위대로 정리한다.

분류 기준은 **필요한 데이터**다. 지금 데이터로 되는 것과 파이프라인이
필요한 것을 섞으면 착수 순서를 못 정한다.

| 구분 | 의미 |
|---|---|
| A | 현재 보유 데이터로 즉시 계산 가능 |
| B | Kaggle 데이터셋에 있으나 모델/화면이 미사용 |
| C | 운영 시스템 연동으로 신규 수집 필요 |

## 완료 (PR #14)

### ① 개입 손익분기점 — "이 고객에게 얼마까지 쓸 수 있나" · 구분 A

```
월 손익분기 할인 = 이탈확률 × 캠페인 성공률 × 월요금
```

기대 구제 매출과 같은 값이다. 여기까지가 본전이고 넘기면 손해다.
테이블에 `할인 상한 /월` 열로, 개입 계획 패널에 합계로 노출.

성공률은 가정값이므로 20/30/50%를 사용자가 고르게 했다. 값을 고정해
숨기면 근거 없는 숫자가 확정처럼 보인다.

### ② 임계값과 정밀도 노출 · 구분 A

기존 UI는 "고위험"을 확정처럼 보여줬지만 **임계값 0.5의 실제 정밀도는
0.498** — 연락 두 건 중 한 건이 헛수고다. 이 사실이 화면 어디에도 없었다.

`train.py`가 테스트셋에서 임계값별 정밀도/재현율을 측정해
`threshold_metrics.json`으로 저장하고, `GET /model-metrics`로 서빙한다.
개입 계획 패널의 슬라이더를 옮기면 대상 수·적중/헛수고·놓치는 이탈
고객·예산 상한이 함께 움직인다.

| 임계값 | 정밀도 | 재현율 | 플래그율 |
|---|---|---|---|
| 0.30 | 0.419 | 0.920 | 0.583 |
| 0.40 | 0.464 | 0.877 | 0.502 |
| 0.50 | 0.498 | 0.807 | 0.430 |
| 0.60 | 0.543 | 0.722 | 0.353 |
| 0.70 | 0.600 | 0.578 | 0.256 |

보간하지 않고 실제 측정 지점만 사용한다. 보간은 측정하지 않은 수치를
지어내는 것과 같다.

### ③ Contract 피처 추가 · 구분 B

What-if 패널에 "계약 유형" 드롭다운이 있었지만 모델이 `Contract`를 보지
않아 **확률이 전혀 움직이지 않았다.** 추천 액션은 "장기계약 전환 유도"라고
말하는데 시뮬레이터로는 그 효과를 보여줄 수 없는 상태였다.

성능 기여는 작다 (AUPRC 0.626 → 0.627). tenure·요금이 이미 같은 분산을
잡고 있기 때문이다. 그럼에도 넣은 이유는 **성능이 아니라 제품 정합성**이다.

부수 효과로 What-if 페이로드가 `TechSupport`/`StreamingTV`/
`StreamingMovies`/`SeniorCitizen` 4개를 누락하던 버그를 발견해 고쳤다.
조작을 하지 않아도 기준선이 달라져, 표시되던 델타에 조작과 무관한 오차가
섞여 있었다.

## 미착수 — 우선순위 순

### ④ tenure 코호트별 위험 곡선 · 구분 A

가입 몇 개월차에 위험이 급증하는지. 지금 대시보드는 **누구에게** 할지는
알려주지만 **언제** 할지는 모른다. 온보딩 개입의 골든타임을 정하는 지표.

- 구현: 코호트(0-6/7-12/13-24/25-48/49+)별 평균 이탈확률 + 실제 이탈률
- 화면: 좌측 컬럼에 라인 차트 1개
- 난이도: 낮음. 업로드 데이터만으로 계산 가능

### ⑤ 부가서비스 부착률 (attach rate) · 구분 B

`OnlineSecurity` / `TechSupport` / `OnlineBackup` / `DeviceProtection`
부착 개수. 락인 강도의 직접 지표이면서, 실행 가능한 액션(무료 체험 제공)과
1:1로 대응된다는 점이 강점이다.

- 미사용 컬럼 2개(`OnlineBackup`, `DeviceProtection`)를 CSV 스펙에 추가
- 부착 0~1개 & 고위험 → "서비스 번들 무료 체험" 캠페인 대상

### ⑥ 개입 결과 추적 루프 · 구분 C ★ 장기적으로 가장 중요

지금은 추천만 하고 결과를 모른다. 캠페인 실행 → 30/60/90일 후 실제 이탈
여부 → 리프트 측정이 없으면 **대시보드가 학습하지 못한다.**

- 필요 데이터: 캠페인 발송 로그, 고객별 실제 이탈 시점
- 측정: 개입군 vs 대조군 이탈률 차이 (홀드아웃 필수)
- 이것이 있어야 ①의 "캠페인 성공률" 가정값이 실측값으로 바뀐다

### ⑦ 자발적 vs 비자발적 이탈 분리 · 구분 C

청구 실패·카드 만료로 인한 이탈은 리텐션 캠페인이 아니라 결제 수단 갱신
안내로 대응해야 한다. 현재 모델은 둘을 섞어 학습하고 있다.

### ⑧ 선행 지표 (사용량 급감, 문의 급증, NPS) · 구분 C

현재 피처는 전부 계약·요금 스냅샷이라 **변화**를 포착하지 못한다.
"지난달 대비 사용량 40% 감소" 같은 신호가 들어오면 예측 시점을 앞당길 수
있다. 데이터 파이프라인 비용이 가장 큰 항목.

## 참고 — 미사용 컬럼의 단변량 신호 강도

전체 이탈률 26.5% (n=7,043) 기준, 값별 이탈률 최대-최소 격차:

| 컬럼 | 격차 | 상태 |
|---|---|---|
| Contract | 39.9%p | ✅ PR #14에서 추가 |
| InternetService | 34.5%p | 미사용 |
| PaymentMethod | 30.0%p | 사용 중 |
| PaperlessBilling | 17.2%p | 미사용 |
| Dependents | 15.8%p | 미사용 |

`InternetService`(Fiber optic 41.9% vs No 7.4%)는 회선 품질 이슈를
반영하는 신호로 보인다. 다만 Contract와 마찬가지로 증분 기여는 작을 수
있으므로(+Contract+InternetService 조합에서 AUPRC 0.631), 추가한다면
성능보다 세그먼트 분석 목적이 맞다.

**교훈**: 단변량 신호 강도와 모델 증분 기여는 다르다. Contract는 단일
신호로는 가장 강했지만 tenure·요금과 정보가 겹쳐 AUPRC를 0.001 올렸다.
